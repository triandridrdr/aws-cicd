================================================================================
END-TO-END CI/CD PIPELINE: GITHUB -> ECR -> ECS FARGATE MENGGUNAKAN CODEPIPELINE
================================================================================

KOMPONEN ARSITEKTUR:
1. GitHub                     : Repository Source Code
2. AWS CodeBuild              : CI (Build project & Push Docker image ke ECR)
3. AWS ECR                    : Registry penyimpanan Docker image
4. AWS ECS Fargate            : CD / Serverless runtime eksekusi container
5. AWS CodePipeline           : Otomatisasi orkestrasi (Source -> Build -> Deploy)

================================================================================
BAGIAN 1: PERSIAPAN REPOSITORY GIT & DOCKERFILE
================================================================================
Jalankan perintah ini di root folder project lokal Anda:

git init
git add .
git commit -m "feat: initial commit"
git branch -M main
git remote add origin https://github.com/triandridrdr/aws-cicd.git
git push -u origin main

BAGIAN 2: MEMBUAT AMAZON ECR (IMAGE REGISTRY)
================================================================================
1. Buka AWS Console -> cari "Elastic Container Registry" (ECR).
2. Klik tombol "Create repository".
3. Konfigurasi repository:
   - General settings : Pilih "Private"
   - Repository name  : sample-repo
   - Biarkan opsi lain default.
4. Klik tombol "Create repository".
5. Catat URI repository yang terbuat:
   URI: 518501464729.dkr.ecr.ap-southeast-2.amazonaws.com/sample-repo

[PENTING]: Nama repository ("sample-repo") HARUS sama persis dengan yang
dipakai di variabel REPOSITORY_URI pada buildspec (Bagian 3) dan Image URI pada
Task Definition (Bagian 5.1). Repository harus dibuat lebih dulu, karena
"docker push" tidak akan membuat repository secara otomatis.


================================================================================
BAGIAN 3: KONFIGURASI BUILDSPEC DI ROOT PROJECT
================================================================================
[PENTING]: Agar CodePipeline dapat mengupdate Task Definition di ECS secara
otomatis saat deployment, CodeBuild HARUS memproduksi output file bernama
"imagedefinitions.json".

[PENTING - NAMA FILE]: Nama file buildspec di repo ini adalah
"buildspec.yaml" (ekstensi .yaml). CodeBuild secara default mencari
"buildspec.yml", jadi pada Bagian 4 kolom "Buildspec name" WAJIB diisi
"buildspec.yaml" (sesuai nama file sebenarnya di repo). Jika Anda memakai nama
lain, nama di repo dan di CodeBuild harus sama persis.

[PENTING - BUILD JAR]: Dockerfile menjalankan "COPY target/course-service.jar".
File JAR itu hanya ada jika Maven dijalankan SEBELUM "docker build". Karena itu
buildspec harus memuat "mvn clean install" (tanpa itu docker build gagal:
"target/course-service.jar: not found"). Java 17 + Maven dipastikan tersedia
lewat "runtime-versions" di fase install.

Pastikan file buildspec di root project Anda memiliki format berikut:

version: 0.2

phases:
  install:
    runtime-versions:
      java: corretto17
  pre_build:
    commands:
      - echo Running Maven build...
      - mvn clean install
      - echo Logging in to Amazon ECR...
      - aws --version
      - REGION=ap-southeast-2
      - ACCOUNT_ID=518501464729
      - ECR_REGISTRY=$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com
      - REPOSITORY_URI=$ECR_REGISTRY/sample-repo
      - aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $ECR_REGISTRY
      - IMAGE_TAG=build-$(echo $CODEBUILD_BUILD_ID | awk -F":" '{print $2}')
  build:
    commands:
      - echo Build started on `date`
      - echo Building the Docker image...
      - docker build -t $REPOSITORY_URI:latest .
      - docker tag $REPOSITORY_URI:latest $REPOSITORY_URI:$IMAGE_TAG
  post_build:
    commands:
      - echo Build completed on `date`
      - echo Pushing the Docker images...
      - docker push $REPOSITORY_URI:latest
      - docker push $REPOSITORY_URI:$IMAGE_TAG
      - echo Writing image definitions file...
      # DOCKER_CONTAINER_NAME harus sama persis dengan nama container di ECS Task Definition
      - DOCKER_CONTAINER_NAME=sample-container
      - printf '[{"name":"%s","imageUri":"%s"}]' $DOCKER_CONTAINER_NAME $REPOSITORY_URI:$IMAGE_TAG > imagedefinitions.json
      - cat imagedefinitions.json
artifacts:
  files:
    - imagedefinitions.json

Catatan: "mvn clean install" juga menjalankan unit test (contextLoads). Jika
test gagal, build berhenti. Tag image "build-<id>" unik per build, sehingga
setiap deploy selalu memakai image yang benar-benar baru (bukan "latest").

[CATATAN]: Pastikan REPOSITORY_URI di buildspec yang dipakai CodeBuild di
repo Anda sudah mengarah ke "sample-repo" (bukan nama repository lama).
Jika masih berbeda, build akan gagal saat push (repository tidak ditemukan).

[PENTING - NAMA CONTAINER]: Nilai "name" di imagedefinitions.json
("sample-container") HARUS sama persis dengan "Name" container di ECS Task
Definition (Bagian 5.1). Jika berbeda (misal buildspec masih memakai nama lama
"javatechie-container"), stage Deploy CodePipeline gagal dengan error
"container name not found in task definition". Di buildspec yang menggunakan
variabel, samakan DOCKER_CONTAINER_NAME=sample-container.

Simpan, lalu push perubahan ke GitHub:
git add buildspec.yaml
git commit -m "ci: add buildspec with imagedefinitions artifact"
git push origin main

BAGIAN 4: MEMBUAT DAN KONFIGURASI AWS CODEBUILD
================================================================================
1. Buka AWS Console -> cari "CodeBuild" -> klik "Create build project".
2. Project configuration:
   - Project name: sample-project
     (Nama ini harus sama persis dengan "Project name" di Build stage
      CodePipeline pada Bagian 6, dan nama service role di bawah.)
3. Source:

   - Repository      : Connect using OAuth / Personal Access Token
   - Repository URL  : https://github.com/triandridrdr/aws-cicd.git
4. Environment:
   - Environment image : Managed image
   - Compute           : EC2
   - Operating system  : Amazon Linux (atau Ubuntu standard)
   - Runtime(s)        : Standard
   - Image             : image "standard" versi 5.0 atau lebih baru (sudah berisi
                         Maven, Docker, dan mendukung Java corretto17)
   - Image version     : Always use the latest image for this runtime version
   - Environment type  : Linux
   - [WAJIB CENTANG]   : "Privileged" (Enable this flag if you want to build Docker images)
   - Service role      : New service role (Name: sample-project-role)

   - Pilih: "Use a buildspec file"

6. Artifacts:
   - Type: No artifacts (karena artifact akan diatur otomatis oleh CodePipeline)
7. Klik tombol "Create build project".

   Langkah ini WAJIB sukses sebelum lanjut ke Bagian 5, karena Task Definition
   membutuhkan image "sample-repo:latest" sudah ada di ECR.

BAGIAN 5: MENYIAPKAN INFRASTRUKTUR AWS ECS FARGATE
================================================================================
HIERARKI STRUKTUR:
                     [ ECS Cluster ]
             (Rumah besar / Batas Lingkungan)
                            |
                            v
                     [ ECS Service ]
             (Pengawas / Manajer Operasional)
                 /          |          \
                v           v           v
           [ Task 1 ]  [ Task 2 ]  [ Task 3 ]
       (Aplikasi Nyala / Instansiasi Nyata)
               |            |            |
               v            v            v
          [Container]  [Container]  [Container]
        (Wadah Docker)

Catatan Port 8080:
Port 8080 muncul berulang kali karena ia adalah port tempat aplikasi
mendengarkan (listen) di dalam container, dan setiap "pintu" yang dilalui
trafik harus diarahkan ke port yang sama itu. Jika salah satu berbeda,
koneksi gagal (timeout / connection refused).

Alur trafik dari browser sampai aplikasi:

  Browser (http://<PUBLIC_IP>:8080)
        |
        v
  Security Group Inbound (TCP 8080)   <- firewall di ENI task, harus mengizinkan 8080
        |
        v
  Task Definition Port Mapping (container port 8080)
        |
        v
  Aplikasi Spring Boot listen di 8080 (default Spring Boot, server.port)

Peran masing-masing:
1. Aplikasi (Spring Boot)
   - Default listen di port 8080. Di project ini tidak ada "server.port" di
     application.properties, jadi memakai default 8080.
   - Inilah sumber angka 8080; semua pengaturan lain mengikutinya.
2. Dockerfile (EXPOSE 8080)
   - Hanya dokumentasi/metadata bahwa container memakai 8080.
   - TIDAK membuka akses apa pun dan tidak wajib agar aplikasi berjalan.
3. Task Definition - Port mapping (Container port 8080)
   - Memberi tahu ECS port mana di dalam container yang diteruskan.
   - Pada Fargate (mode jaringan awsvpc), task punya ENI/IP sendiri, sehingga
     port container = port yang diakses dari luar (tidak bisa dipetakan ke
     port lain seperti 80:8080 di Docker biasa).
4. Security Group - Inbound rule (TCP 8080)
   - Firewall pada task. Tanpa rule ini trafik ke 8080 diblokir meskipun
     aplikasi sudah berjalan.
   - Source 0.0.0.0/0 hanya untuk uji coba; untuk produksi batasi ke IP
     tertentu atau pakai Load Balancer.
5. URL Browser (:8080)
   - Port harus ditulis eksplisit karena browser default ke 80/443.

Catatan tambahan:
- Port 8080 bukan angka wajib. Jika aplikasi diubah ke port lain (misal 9090
  lewat "server.port=9090"), ubah juga EXPOSE, Port mapping, Security Group,
  dan URL browser ke 9090.
- Jika nanti memakai Application Load Balancer, port listener ALB boleh
  berbeda (misal 80/443), tetapi Target Group tetap harus mengarah ke 8080 dan
  Security Group task harus mengizinkan trafik dari ALB ke 8080.
- Gejala jika salah:
  * Timeout            -> Security Group belum mengizinkan 8080 atau Public IP
                          belum aktif.
  * Connection refused -> port di Task Definition tidak sesuai dengan port
                          aplikasi.

LANGKAH 5.1: MEMBUAT TASK DEFINITION ("Buku Resep")
--------------------------------------------------------------------------------
1. Buka AWS Console -> "Amazon Elastic Container Service" (ECS).
2. Di menu kiri, klik "Task definitions" -> klik "Create new task definition".
3. Task definition family: ecs-task
4. Infrastructure requirements / Launch type:
   - Pilih: AWS Fargate
   - Operating system/Architecture: Linux/X86_64
5. Task size:
   - CPU    : 0.25 vCPU
   - Memory : 1 GB
     (Jangan 0.5 GB: JVM Spring Boot + Swagger sering kehabisan memori di
      0.5 GB sehingga task berulang kali berhenti dengan exit code 137 / OOM.
      Kombinasi 0.25 vCPU + 1 GB valid di Fargate.)
6. Task execution role: biarkan default "Create new role" (ecsTaskExecutionRole).
   Role ini WAJIB ada agar Fargate bisa menarik (pull) image dari ECR private
   dan menulis log ke CloudWatch.
7. Container details:
   - Name         : sample-container
   - Image URI    : 518501464729.dkr.ecr.ap-southeast-2.amazonaws.com/sample-repo:latest
   - Port mappings:
     * Container port : 8080
     * Protocol       : TCP
     * App protocol   : HTTP
8. Klik tombol "Create".

--------------------------------------------------------------------------------
LANGKAH 5.2: MEMBUAT CLUSTER ("Gedung / Area Kerja")
--------------------------------------------------------------------------------
1. Di menu kiri, klik "Clusters" -> klik "Create cluster".
2. Cluster name: ecs-cluster
3. Infrastructure: Pastikan opsi "AWS Fargate (serverless)" tercentang.
4. Klik tombol "Create".

--------------------------------------------------------------------------------
LANGKAH 5.3: MEMBUAT SERVICE ("Manajer Operasional")
--------------------------------------------------------------------------------
1. Buka cluster: "ecs-cluster".
2. Buka tab "Services" -> klik tombol "Create".
3. Deployment configuration:
   - Application type : Service
   - Family           : ecs-task
     (Harus sama dengan Task definition family di Langkah 5.1. Pipeline tidak
      memakai nama ini secara langsung: stage Deploy mengambil task definition
      dari Service lalu membuat revision baru, jadi family tidak perlu
      dimasukkan di CodePipeline maupun buildspec.)
   - Revision         : latest
   - Service name     : ecs-service
   - Desired tasks    : 1
4. Networking:
   - VPC & Subnets: Default VPC dan centang semua Subnet yang ada.
   - Security group: Create a new security group
     * Security group name : sample-sg
     * Inbound rules       :
       - Type   : Custom TCP
       - Port   : 8080
       - Source : Anywhere-IPv4 (0.0.0.0/0)
       (Console biasanya mengisi rule default port 80 sesuai port mapping;
        pastikan rule yang tersisa adalah TCP 8080, hapus/ubah rule lain.)
   - Public IP: Turned ON
     (WAJIB aktif. Tanpa Public IP dan tanpa NAT Gateway, task tidak bisa
      menarik image dari ECR dan gagal dengan "CannotPullContainerError".)
5. Klik tombol "Create".

--------------------------------------------------------------------------------
LANGKAH 5.4: PENGUJIAN AWAL SEBELUM PIPELINE
--------------------------------------------------------------------------------
1. Buka cluster "ecs-cluster" -> tab "Tasks".
2. Klik Task ID yang berstatus "Running".
3. Di bagian "Configuration" / "Network interfaces", salin "Public IP" (misal: 3.27.56.127).
4. Uji endpoint dasar lebih dulu (paling andal):
   http://<PUBLIC_IP>:8080/courses/health    -> harus menampilkan: UP
   http://<PUBLIC_IP>:8080/courses/welcome   -> pesan sambutan
5. Lalu buka Swagger UI:
   http://<PUBLIC_IP>:8080/swagger-ui/index.html
   [CATATAN]: pom.xml memakai springdoc-openapi 2.0.4 bersama Spring Boot
   3.2.5. Versi springdoc ini dibuat untuk Spring Boot 3.0.x dan dapat
   menampilkan "Failed to load API definition" (/v3/api-docs error 500) di Boot
   3.2.x. Jika /courses/health berhasil tetapi Swagger error, pipeline Anda
   sudah benar; perbaiki dengan menaikkan versi springdoc di pom.xml ke 2.3.0
   atau lebih baru.

BAGIAN 6: MEMBUAT PIPELINE OTOMATIS (AWS CODEPIPELINE)
================================================================================
Tahap ini menggabungkan Source, Build, dan Deploy agar setiap git push akan
otomatis mengupdate container di ECS tanpa intervensi manual.

1. Buka AWS Console -> cari "CodePipeline" -> klik "Create pipeline".
2. Pipeline settings:
   - Pipeline name : sample-pipeline
   - Pipeline type : V2 (atau V1 default)
   - Execution mode: Queued / Superseded
   - Service role  : New service role (biarkan nama default terisi)
   - Klik "Next".

3. Source stage (Tahap Ambil Kode):
   - Source provider : GitHub (Version 2)
   - Connection      : Klik "Connect to GitHub", beri nama koneksi, selesaikan otentikasi di popup.
   - Repository name : triandridrdr/aws-cicd
   - Default branch  : main
   - Trigger         : Pastikan opsi deteksi push aktif (Start the pipeline on source code change).
   - Output artifact format: CodePipeline default.
   - Klik "Next".

4. Build stage (Tahap Build & Push ECR):
   - Build provider : AWS CodeBuild
   - Region         : ap-southeast-2 (sesuaikan dengan region Anda)
   - Project name   : sample-project
   - Build type     : Single build
   - Klik "Next".

5. Deploy stage (Tahap Deploy ke Fargate):
   - Deploy provider : Amazon ECS
   - Region          : ap-southeast-2 (sesuaikan dengan region Anda)
   - Cluster name    : ecs-cluster
   - Service name    : ecs-service
   - Image definitions file: imagedefinitions.json
     (File ini dibuat otomatis oleh buildspec pada bagian post_build)
   - Deployment timeout: biarkan default (atau 10-15 menit).
   - Klik "Next".

6. Review:
   - Periksa seluruh konfigurasi dari Source -> Build -> Deploy.
   - Klik tombol "Create pipeline".

================================================================================
BAGIAN 8: TROUBLESHOOTING (ERROR UMUM)
================================================================================
Stage Build gagal:
- "stat buildspec.yml: no such file"
    -> Isi "Buildspec name" di CodeBuild dengan buildspec.yaml (Bagian 4).
- "target/course-service.jar: not found" pada docker build
    -> Buildspec belum menjalankan "mvn clean install" (Bagian 3).
- "Cannot connect to the Docker daemon"
    -> Opsi "Privileged" di CodeBuild belum dicentang.
- "AccessDeniedException / no basic auth credentials / not authorized" saat
  login/push ke ECR
    -> Policy AmazonEC2ContainerRegistryPowerUser belum dipasang di role
       sample-project-role.
- "name unknown: The repository ... does not exist"
    -> Nama repository di buildspec tidak sama dengan "sample-repo" di ECR,
       atau region/account salah.
- Maven test gagal
    -> Lihat log; perbaiki test atau kode sebelum push.

Stage Deploy gagal:
- "container name not found" / tidak ada perubahan image
    -> Nama container di imagedefinitions.json (DOCKER_CONTAINER_NAME) tidak
       sama dengan "sample-container" di Task Definition.
- "Service not found"
    -> Cluster/service di CodePipeline tidak sama dengan ecs-cluster /
       ecs-service, atau region berbeda.
- Deploy "In progress" lama lalu gagal, task terus restart
    -> Cek ECS -> Service -> tab Logs/Events dan "Stopped reason" pada task:
       * exit code 137 / OutOfMemory -> naikkan memory task (>= 1 GB).
       * CannotPullContainerError    -> Public IP belum aktif, atau image/tag
                                        belum ada di ECR.
       * Task failed to start (execution role) -> pastikan ecsTaskExecutionRole
                                        terpasang di Task Definition.

Aplikasi tidak bisa diakses dari browser:
    -> Lihat "Catatan Port 8080" di Bagian 5 (Security Group, Public IP, port).
